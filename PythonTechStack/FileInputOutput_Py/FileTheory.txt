## 1. The Core Lifecycle: Open, Work, Close
Every time you deal with a file in Python, you must follow three fundamental steps:

   1. Open the file (this creates a connection or "stream" from your script to the file).
   2. Work with the file (Read the content or Write new data into it).
   3. Close the file (this breaks the connection and saves changes safely to the drive).

------------------------------
## 2. The Built-in open() Function
Python uses the global open() function to establish a connection to a file. It takes two primary arguments:

file_object = open("filename.txt", "mode")


* Filename: The name or path of the target file.
* Mode: A single letter telling Python exactly what you intend to do with the file.

## The 4 Essential File Modes

| Mode | Name | What it Does | Safety Check |
|---|---|---|---|

| "r" | Read | Opens a file purely to look at its contents. | Crashes (FileNotFoundError) if the file does not exist. |

| "w" | Write | Creates a new file to type data into. | Danger: If the file already exists, it completely erases (overwrites) all old content. |

| "a" | Append | Opens a file to add data onto the absolute end. | Safe: Keeps existing content intact and adds new text down at the bottom. Creates the file if it doesn't exist. |

| "x" | Exclusive | Creates a brand-new file to write into. | Safe: Automatically crashes with an error if the file already exists, preventing accidental deletion. |

------------------------------
## 3. Reading Methods Explained
Assume we have a file named sample.txt containing:
## Method A: .read()
Reads the entire file at once into one single, giant string string block.

f = open("sample.txt", "r")content = f.read()
print(content)
f.close()

## Method B: .readline()
Reads the file one line at a time. Every time you call it, it advances down to the next row.

f = open("sample.txt", "r")first_line = f.readline()   # Reads line 1second_line = f.readline()  # Reads line 2
print(first_line)
f.close()

## Method C: .readlines()
Reads the entire file and breaks it up line-by-line into a Python list of strings.

f = open("sample.txt", "r")lines_list = f.readlines()  # Result: ['Line 1...\n', 'Line 2...\n']
f.close()

------------------------------
## 4. Writing & Appending Methods## Writing ("w") — The Destructive Method

f = open("output.txt", "w")
f.write("This completely replaces old text.\n")
f.close()

## Appending ("a") — The Safe Addition Method

f = open("output.txt", "a")
f.write("This adds safely to the absolute bottom of the file.\n")
f.close()

------------------------------
## 5. Best Practice: The with Statement (Context Manager)
In professional production code and data engineering pipelines, you should almost never use f.close() manually. If your code hits an unexpected error or crashes halfway through processing, the line f.close() is skipped, leaving the file corrupted or locked in system memory.
Instead, use the with statement. It creates a temporary context block and automatically closes the file for you, even if your code crashes inside the block.

#  THE PROFESSIONAL WAY:with open("sample.txt", "r") as f:
    data = f.read()
    print(data)# Look, no f.close() needed! Python shuts the door automatically right here.

------------------------------
## 6. Text Files (t) vs. Binary Files (b)

* Text Mode ("rt", "wt"): Used for human-readable content like .txt, .csv, or .html files. The t flag is optional and applied by default.
* Binary Mode ("rb", "wb"): Used for files that are not plain text, such as images (.png, .jpg), videos, or compiled datasets. Python reads these as a raw stream of bytes instead of characters.

------------------------------
## 💡 Data Engineering Tip for Your Notebook
When working with file reading loops, you can iterate over a file object directly using a for loop. This avoids loading a massive 10GB file into your RAM all at once:

# Highly memory efficient for massive data fileswith open("huge_dataset.txt", "r") as file:
    for line in file:
        if "ERROR" in line:
            print(line.strip())

# VV IMP FOR PATH LIBRARY
In standard Python, managing file locations across different folders used to be done with the old os.path module, which treated paths as simple strings.
pathlib is a built-in Python module introduced to replace the old string-based system. It introduces Path, which treats file and folder directions as smart objects rather than raw text strings.
------------------------------
## Why Use pathlib over Old Alternatives?
Historically, if you wanted to join a folder name and a file name together, you had to write string operations like folder + "/" + file. This caused significant issues:

* The Slash Problem: Windows uses backslashes (\) for file paths, while Mac and Linux use forward slashes (/). A path hardcoded with strings on a Mac would instantly crash on a Windows computer.
* pathlib fixes this perfectly. It automatically detects whether your user is running Windows, Mac, or Linux and flips the slashes to match the operating system behind the scenes.

------------------------------
## Core Structural Features of Path
Here is a summary cheat sheet of the most important Path attributes and methods you will use in your file chapters:

| Feature / Method | What it Returns / Does | Use Case Example |
|---|---|---|
| Path(__file__) | The absolute file location of the current running script. | Finding where your code is running. |
| .name | Returns just the filename with its extension. | Path("prep/tables/table_7.txt").name $\rightarrow$ "table_7.txt" |
| .stem | Returns just the filename without the extension. | Path("prep/tables/table_7.txt").stem $\rightarrow$ "table_7" |
| .suffix | Returns just the file extension. | Path("prep/tables/table_7.txt").suffix $\rightarrow$ ".txt" |
| .parent | Returns the directory folder containing the file. | Path("prep/tables/table_7.txt").parent $\rightarrow$ "prep/tables" |
| .exists() | Returns True or False depending on if the file is physically there. | Preventing FileNotFoundError crashes before reading. |

------------------------------
## Clean Code Demonstration for Your Notes
Copy-paste this script into your file setup to see how clean path manipulation becomes with object-oriented logic:

from pathlib import Path
# 1. Grab the exact location of this python scriptscript_location = Path(__file__)
print(f"This script lives at: {script_location}")
# 2. Travel up one folder level using .parentparent_directory = script_location.parent
print(f"The folder holding this script is: {parent_directory}")
# 3. Join paths cleanly using the / operator!# pathlib overrides the division slash to join folders safely across Windows/Macnew_file_path = parent_directory / "tables" / "sample_log.txt"
print(f"Generated target location: {new_file_path}")
# 4. Check if a folder exists safelyif not new_file_path.parent.exists():
    print("The 'tables' folder doesn't exist yet. Creating it now...")
    new_file_path.parent.mkdir(parents=True, exist_ok=True)
# 5. Write and read text in ONE single line without manual .close() steps
new_file_path.write_text("Log entry: Pathlib is configured properly.")
print(f"File contents read back instantly: '{new_file_path.read_text()}'")

## Key Takeaway for Data Scientists
When building data engineering pipelines or handling training datasets, you have to read thousands of data files spread across subfolders. Using Path allows you to search, filter, create, and write to directories cleanly using intuitive dot-notation methods without worrying about operating system incompatibilities.
